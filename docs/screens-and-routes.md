# 화면과 라우트

> 상태: **제안**. 디자인이 나오면 갱신한다. 운동·코칭 화면의 상세는 담당자가 확정한 뒤 채운다.

| 화면        | 경로                  | 인증   | 설명                                            | 상태                      |
| ----------- | --------------------- | ------ | ----------------------------------------------- | ------------------------- |
| 로그인      | `/login`              | 불필요 | 로그인(아이디, 카카오)                                          | 제안                      |
| 회원가입    | `/signup`             | 불필요 | 회원가입, 출산 예정일·운동 경험 등 기본 정보 입력 | 제안                      |
| 카카오 콜백 | `/auth/callback` | 불필요 | 카카오 로그인 뒤 세션 복구 결과에 따라 `/home` 또는 `/onboarding`으로 이동 | 제안 |
| 온보딩 | `/onboarding` | 필요(온보딩 전) | 카카오로 처음 가입한 사용자의 동의·출산 예정일·운동 경험 입력, 의학적 면책 문구 | 제안 |
| 비밀번호 재설정 | `/password/reset` | 불필요 | 이메일 인증 후 새 비밀번호 설정 | 제안 |
| 탈퇴 계정 복구 | `/account/restore` | 불필요(로그인 상태면 `/home`) | 탈퇴 유예 중인 계정이 로그인(아이디·카카오)하면 오는 화면. 삭제 예정일을 보여주고 "계정 복구하기"/"복구하지 않기" 선택 | 구현 |
| 랜딩 | `/` | 불필요 | 서비스 소개, 로그인 상태에 따라 시작·홈 이동 버튼 | 제안 |
| 홈 | `/home` | 필요 | 살구색 슬라이드 히어로(문구·사진 3장, 모든 버튼이 `/workouts`로 이동)와 내 상태·출산 예정일(D-N)·이번 주 운동 카드. 이번 주 운동은 "N일 운동했어요"(기록이 없으면 "첫 운동을 시작해 볼까요?"), 월~일 요일·날짜(운동을 마친 날은 체크), 오늘 운동 완료 표시, 응원 한마디로 구성하고 목표 횟수는 없다. "운동 기록 보기"는 `/records`로 이어진다. 오른쪽 아래에 챗봇 캐릭터 "피치"가 떠 있고, 누르면 채팅창이 열린다([chatbot-api.md](chatbot-api.md)) | 구현 |
| 운동 기록 | `/records` | 필요 | 내 운동 기록 캘린더. 월 단위로 넘기며(다음 달은 이번 달까지), 운동을 마친 날을 살구색 칸과 점으로 표시한다. 날짜를 고르면 오른쪽 카드가 그 날짜로 바뀐다. 카드 안에는 그 날짜의 AI 에이전트 리포트(`POST /api/agent/daily-report`, `features/agent-report`)를 보여준다. 한마디, 다음 집중 스텝, 운동 시간·횟수와 기록별 완료 세트/목표 세트, 자세 배우기 스텝별 최고점·통과 횟수, 안전 안내 순서다. 지난 날짜는 서버가 그날 만든 리포트를 그대로 돌려주므로 한 번 받으면 다시 부르지 않고, 오늘은 다시 고르면 다시 부른다(새 기록이 없으면 서버가 저장한 리포트를 돌려준다). 아직 오지 않은 날은 부르지 않는다. 리포트 캐시는 사용자별이라 같은 탭에서 다른 계정으로 로그인하면 지난 날짜도 그 계정의 리포트를 새로 부른다. 다른 기능이라 `RecordsPage`가 로그인한 사용자 번호와 함께 `RecordsView`의 `renderReport`로 넘긴다. 좁은 화면은 위아래로 쌓고 lg 이상에서 좌우로 나눈다. `GET /api/exercise-records?from=&to=`(KST 날짜, 최대 62일)로 조회 | 구현 |
| 운동 목록   | `/workouts`           | 필요   | 운동 종류 선택. 운동이 정해지기 전까지는 "준비 중" 안내만 보여준다 | 임시 구현                 |
| 운동 모드   | `/workouts/:id`       | 필요   | 웹캠 실시간 자세 분석과 피드백                  | **미정**                  |
| 자세 배우기 | `/workouts/:id/learn` | 필요   | 스텝별 음성 코칭                                | **미정**                  |
| 운동 리포트 | `/reports/:id`        | 필요   | 운동 종료 후 점수, 횟수, 낮은 점수 스텝         | 제안 (데이터 형태는 미정) |
| 대시보드    | `/dashboard`          | 필요   | 주간 현황, 장기 추이 차트                       | 제안                      |
| AI 에이전트 | `/agent`              | 필요   | 임신 관련 Q&A, 맞춤 정보                        | 제안                      |
| 관리자 | `/admin` | 필요(관리자만) | 관리자 대시보드. 일반 사용자는 `/home`으로 보낸다(`RequireAdmin`). 화면 코드는 lazy import로 관리자가 들어갈 때만 내려받는다. 위에서부터 "오늘 현황" 요약 카드 5개(전체 회원·오늘 방문·오늘 가입·오늘 완료한 운동·탈퇴 유예 중), 필터 한 줄(최근 7/30/90일, 일/주/월별), 방문자 수 추이(일별=DAU, 주별=WAU, 월별=MAU, 카드 위에 오늘·최근 7일·최근 30일 방문자)→ 가입·탈퇴 추이 → 운동별 완료 횟수 순서이고, 카드는 한 줄에 하나씩 전체 폭으로 쌓는다. 운동별 완료 횟수는 운동마다 한 줄씩 그린 꺾은선 추이이고(운동 색은 id 순서로 고정, 8개를 넘으면 "기타"로 묶음), 범례에 선택한 기간의 운동별 합계·평균 점수를 직접 적으며 모든 운동을 합친 총 횟수는 보여 주지 않는다. 카드 위에는 가장 많이 한 운동이 나온다. 주·월 단위의 첫 구간은 기간 앞쪽 날짜까지 포함해 구간 전체를 세고(첫 막대가 낮아 보이지 않게), 합계·평균·종류별은 선택한 기간만 센다. 방문자는 로그인한 일반 회원이 그날 로그인·토큰 갱신으로 기록된 `daily_visits` 기준이며 비로그인 방문자는 세지 않는다. 모든 차트는 "표로 보기"를 가지며 필터를 바꿔 다시 불러오는 동안 이전 차트를 흐리게 둔다. 서버 집계는 `GET /api/admin/stats/{summary,exercises,users,visits}`(KST, 일반 회원만, 개인 정보 없음). 관리자 계정은 헤더에 "관리자" 링크만 보이고 로고도 `/admin`으로 간다 | 뼈대 |
| 관리자 회원관리 | `/admin/members` | 필요(관리자만) | 일반 회원 목록. 닉네임·이메일·아이디 검색, 상태(전체/이용 중/탈퇴 유예) 필터, 20명씩 페이지. 검색 조건은 주소(`?q=&status=&page=`)에 담겨 상세에서 돌아와도 유지된다. 관리자 계정은 목록에 없다. 화면 위에는 관리자 탭(현황/회원관리)이 있다 | 구현 |
| 관리자 회원 상세 | `/admin/members/:id` | 필요(관리자만) | 프로필(가입 방식·가입일·마지막 방문·최근 30일 방문·온보딩·운동 경험·출산 예정일·완료한 운동), 최근 운동 기록 10건, 처리 이력 20건. 열 때마다 서버에 조회 이력이 남아 한 번 받은 값은 다시 받지 않는다. "강제 탈퇴"(유예 상태로, 로그인 해제)와 "탈퇴 복구"는 확인 창을 거친다. 관리자 계정이나 없는 id는 "회원을 찾을 수 없어요" | 구현 |
| 내 정보 | `/me` | 필요 | 프로필 조회(읽기 전용)와 "수정하기"로 여는 수정 폼(닉네임·출산 예정일·운동 경험), 회원 탈퇴 | 제안 |

## 화면 폭

기본은 모바일 폭의 단일 컬럼이고, `/me`는 1024px 이상에서 요약 카드와 정보 카드로 나뉘는 넓은 레이아웃을 쓴다. 자세한 내용은 [design.md](design.md#화면-폭)를 참고한다.

## 라우팅 규칙

- `/`는 누구나 볼 수 있는 랜딩이다. 로그인 여부와 상관없이 로그인 화면으로 보내지 않는다.
- 인증이 필요한 경로는 보호 라우트로 감싼다. 로그인하지 않았으면 `/login`으로 보낸다.
- 로그인한 사용자가 `/login`, `/signup`, `/password/reset`, `/account/restore`에 접근하면 `/home`으로 보낸다. 보호 경로에서 `/login`으로 넘어온 경우에는 로그인 후 원래 경로로 보낸다.
- 관리자 계정은 홈·운동·운동 기록·내 정보(`RequireMember`)에 들어가면 `/admin`으로 보낸다. 로그인 직후 `/home`으로 가는 경우도 같다. 내 정보에는 회원 탈퇴가 있어 관리자가 실수로 계정을 잃지 않게 막는 목적도 있다.
- 존재하지 않는 경로는 404 화면을 보여준다.

## 미정

- 운동 모드와 자세 배우기 화면의 구성, 운동 종류별 분기 방식
- 리포트에 표시할 지표와 데이터 형태

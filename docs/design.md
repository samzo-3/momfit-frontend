# 디자인

> 상태: **임시**. 공식 디자인이 나오기 전까지 [apple.com/kr](https://www.apple.com/kr/)의 절제된 스타일을 레퍼런스로 삼는다. 학습용 프로젝트라 스타일 언어만 참고하며, 로고·이미지·문구 같은 자산은 사용하지 않는다.

## 방향

- 흰 바탕과 연회색 영역, 넉넉한 여백, 크고 굵은 제목
- 파란 알약형 주 버튼과 파란 테두리 보조 버튼
- 둥근 흰 카드(`rounded-3xl`)와 둥근 입력(`rounded-xl`), 그림자는 최소한으로

앱 공통 틀은 `src/app/AppLayout.tsx`(반투명 상단 내비게이션 `SiteHeader` + 회색 배경 + `SiteFooter`)다. `SiteFooter`는 모든 화면에 의학적 면책 문구를 보여준다.

**헤더 로고**: `SiteHeader` 왼쪽 위의 서비스명은 글자가 아니라 로고 이미지(`src/assets/momfit-logo.png`, 높이 20px)다. 산호색 `Mom`과 자주색 `Fit`의 둥근 글자체이고, 반투명 헤더 위에서 흰 사각형이 보이지 않도록 **배경을 투명하게** 처리했다(원본은 흰 배경의 2172x724 이미지, 글자 영역만 잘라 457x112로 줄임). 접근성 이름은 `alt="MomFit"`이고, 로그인 상태면 `/home`, 아니면 `/`로 이어진다. 로고를 교체할 때는 투명 배경의 PNG(또는 SVG)를 같은 파일명으로 바꾸고 `width`/`height` 속성의 비율을 맞춘다. 푸터와 랜딩의 `momfit` 글자는 아직 그대로다.

**파비콘과 앱 아이콘**: 브라우저 탭 아이콘은 `MF` 모노그램(산호색 `M`에 임산부 실루엣과 하트, 자주색 `F`)이다. 파일은 `public/`에 두고 `index.html`이 연결한다 — `favicon.ico`(16·32·48px), `favicon-16x16.png`, `favicon-32x32.png`, `apple-touch-icon.png`(180px, iOS 홈 화면). `icon-192.png`와 `icon-512.png`는 `site.webmanifest`(이름 MomFit, 테마색 `#fcf8f4`)가 가리키는 앱 아이콘이다. 아이콘은 흰 배경의 불투명 PNG다. 파일을 바꾸거나 빼면 `src/test/head-assets.test.ts`가 `index.html`과 매니페스트가 가리키는 파일이 실제로 있는지 확인해 실패한다. 기본 Vite 번개 로고(`favicon.svg`)는 삭제했다. 탭 제목은 로고와 같은 표기인 `MomFit`이다(`index.html`의 `<title>`).

## 챗봇 위젯

`/home` 오른쪽 아래에 챗봇 캐릭터 **피치**(굵은 외곽선의 평평한 선화 스타일로, 옅은 복숭아빛 몸통에 갈라진 윗부분·짧은 골·초록 꽃받침과 선으로 그린 새싹이 있고 큼직한 분홍 볼의 얼굴이 있다. `ChatbotMascot` SVG)가 떠 있다. 누르면 채팅창이 열린다. 구성은 `src/features/chatbot`이고 `pages/HomePage.tsx`가 `ChatWidget`을 놓는다.

- 캐릭터 버튼: 64px 원형, `primary` 면에 `primary-strong` 테두리. 아래에 작은 알약 라벨 "물어보기"가 붙고(열려 있을 때는 "닫기"), 라벨과 캐릭터는 하나의 버튼이다. "문의하기"는 고객센터로 오해할 수 있어 쓰지 않는다. 3초 주기로 3px 떠오르는 애니메이션(`--animate-mascot-float`), "동작 줄이기"면 멈춘다.
- 채팅창: 흰 카드(`rounded-3xl`), 위는 `primary` 머리글(캐릭터·이름·닫기), 대화 영역은 `primary-soft` 바탕. 사용자는 `brand` 말풍선(오른쪽), 피치는 흰 말풍선(왼쪽)이다. sm 이상에서는 448px(28rem) 너비에 높이는 화면 높이에서 144px을 뺀 값까지(최대 672px), 좁은 화면에서는 화면 폭에서 좌우 16px을 뺀 너비다. 오른쪽 아래에 고정되어 원래 화면의 UI를 덮어도 된다(버튼과 라벨 위에 놓인다).
- 항상 보이는 안내: 의학적 조언이 아니라는 면책 문구(머리글 아래), "이전 대화는 기억하지 못해요"(첫 인사 안).
- 위험 신호 응답(`emergency`)은 `danger` 색 테두리·글자의 `role="alert"` 말풍선이고, 요청 실패도 `alert`로 알린다.
- 답변의 출처는 말풍선 아래 "출처 N개"를 펼쳐 본다. 기관·나라·확인일을 함께 보여 한국 지침과 구분되게 한다.
- **타자 효과**: 답변(`answer`, `no_answer`, `out_of_scope`)은 25ms마다 글자가 나타난다. 긴 답변도 약 3초 안에 끝나도록 한 번에 나오는 글자 수를 늘린다. 효과는 화면에서만 연출하는 것이라 서버는 답변을 한 번에 보낸다. 아직 나오지 않은 글자는 투명하게 두어 말풍선 크기가 변하지 않고 스크린리더는 전체 문장을 한 번에 읽는다. 위험 신호(`emergency`)와 오류 안내는 효과 없이 바로 보여주고, "동작 줄이기"면 효과를 끈다. 효과 중에 창을 닫으면 다시 열 때 처음부터 치지 않고 전체 글을 보여준다. 출처와 면책 문구는 처음부터 보인다.
- **스크롤**: 질문을 보내면 내 질문과 대기 표시가 보이도록 맨 아래로 내린다. 답변이 도착하면 맨 아래가 아니라 **답변의 시작**이 보이게 맞춘다(긴 답변을 위에서부터 읽도록). 타자 효과가 끝나거나 읽는 중에는 스크롤을 옮기지 않는다.
- 처음에는 예시 질문 3개를 보여주고, 질문한 뒤에는 숨긴다.
- 접근성: 열면 입력칸에 포커스, Esc나 닫기로 닫으면 캐릭터 버튼으로 포커스가 돌아온다. 전송 후에도 포커스는 입력칸에 남는다. 대화 목록은 `role="log"` + `aria-live="polite"`, 닫히는 동안에는 `inert`다.
- 대화는 위젯이 메모리에만 들고 있어서 창을 닫았다 열어도 이어지고, 화면을 벗어나면 사라진다.

## 랜딩 페이지

`/`의 랜딩은 `src/features/landing`의 섹션(`LandingHero`, `FeatureTiles`, `HowItWorks`, `FinalCta`)을 `pages/LandingPage.tsx`에서 조합한다. 흰색과 회색 섹션을 번갈아 배치하고, 로그인 상태는 페이지가 읽어 버튼(`actions`)만 넘긴다. 세션을 복구하는 동안에는 버튼 자리를 비워 두어 잘못된 버튼이 잠깐 보이지 않게 한다. 기능 소개 문구는 기획 기준이라 구현 상태에 맞춰 갱신해야 한다.

## 화면 폭

- 기본 화면은 **모바일 폭의 단일 컬럼**(`max-w-md` 카드)이다. 데스크톱 전용 요구사항은 없어서 대부분의 화면은 이 모양 그대로 쓴다.
- 화면별로 필요할 때만 `lg`(1024px 이상) 변형으로 넓은 레이아웃을 추가한다. 좁은 화면의 모양은 바꾸지 않는다. 지금은 `/me`가 그렇다.
  - `PageShell`의 `wide`: 컨테이너를 `max-w-5xl`로 넓히고 제목을 왼쪽에 두며, 카드는 children이 직접 만든다.
  - `/me`: 왼쪽 프로필 요약 카드(`ProfileSummary`, 좁은 화면에서는 숨김) + 오른쪽 정보·탈퇴 카드. 수정 폼은 닉네임·출산 예정일을 2열로 배치하고 버튼을 오른쪽으로 정렬한다.
- 새 화면은 데스크톱 기준으로 설계하되 단일 컬럼과 최대 폭 제한을 유지해, 좁은 창에서도 깨지지 않게 한다.

## 모션

- 모달처럼 나타나고 사라지는 요소는 `shared/lib/useTransitionState`로 마운트 시점을 조절한다. 열 때는 숨김 상태로 그린 뒤 다음 프레임에 보이게 하고, 닫을 때는 전환이 끝난 뒤에 DOM에서 제거한다. 프레임이 멈추는 환경(백그라운드 탭 등)에서도 투명한 채 남지 않도록 타이머로도 보이게 한다.
- 모달은 들어올 때 200ms `ease-out`(배경 페이드, 패널은 살짝 작은 크기와 아래 8px에서 제자리로), 나갈 때 150ms `ease-in`이다. 나가는 동안 모달은 `inert`라서 눌리거나 포커스를 받지 않는다.
- Tailwind v4의 `scale-*`, `translate-*`는 `transform`이 아니라 개별 속성이므로 전환 대상에 `scale`, `translate`를 명시해야 한다(`transition-[opacity,scale,translate]`).
- **화면 전환**: `src/app/PageTransition.tsx`가 공통 레이아웃(`AppLayout`)에서 화면 내용을 감싸, 경로가 바뀔 때 새 화면이 아래 6px에서 올라오며 220ms 동안 `ease-out`으로 나타난다. 키프레임은 `index.css`의 `--animate-page-in`이다. 경로와 쿼리(`pathname + search`)를 `key`로 쓴다. 그래서 `/workouts?mode=exercise`처럼 쿼리로 단계를 나누는 화면도 이동할 때 재생되고, 같은 경로·쿼리 안의 변화(입력, 세션 복구 후 내용 교체)에는 다시 재생되지 않는다. 헤더와 푸터는 감싸는 영역 밖이라 움직이지 않는다. 나가는 화면은 애니메이션 없이 바로 사라진다(이동이 느려지거나 겹쳐 보이지 않게 하려는 선택이다). 새 화면은 별도 설정 없이 자동 적용된다.
- OS의 "동작 줄이기"(`prefers-reduced-motion`)가 켜져 있으면 전환 없이 즉시 나타나고 사라진다.

## 입력칸 모양

- 평소: 진한 회색(`field`, `#86868b`) 테두리, 모서리 12px, 흰 배경.
- 오류: 연한 분홍 배경(`danger` 6%), 빨간 테두리·입력 글자·라벨. 입력칸 아래에 **원 안의 느낌표 아이콘 + 12px 빨간 안내**를 보여준다(아이콘은 스크린리더에서 숨김).
- 플로팅 라벨은 비어 있고 포커스가 없을 때만 칸 안 세로 중앙(17px)에 놓고, 값이 있거나 포커스를 받으면 위쪽(12px)으로 올린다. 날짜 입력은 브라우저 기본 날짜 표시가 칸 안에 있어 라벨을 칸 위에 두고, 도움말은 라벨 옆 `InfoTip`으로 둔다(회원가입의 출산 예정일).

## 아이디 중복 확인 (회원가입)

- 별도 버튼 줄 없이 아이디 입력칸 **안 오른쪽 한 자리**에서 상태가 바뀐다: 형식이 맞으면 `중복 확인` 텍스트 버튼 → 확인 중 로딩 아이콘 → 사용 가능이면 초록 체크, 이미 사용 중이면 빨간 느낌표(+ 오류 스타일과 칸 아래 오류 문구).
- "사용 가능한 아이디입니다." 문구는 화면에는 보이지 않고 스크린리더(`role="status"`)에만 읽힌다.
- "이미 사용 중인 아이디입니다."도 칸 아래에 쓰지 않고 **빨간 느낌표 아이콘의 툴팁**(아이콘 오른쪽의 흰 말풍선·검은 글자, 나타난 직후 3초간 자동으로 열림)으로 보여준다. 오류 문구는 `TextField`의 `hideErrorMessage`로 화면에서만 숨기고 스크린리더에는 `role="alert"`로 알린다.

## 이메일 인증 입력

아이디 중복 확인과 같은 방식으로, 버튼은 칸 안 오른쪽에서 상태에 따라 바뀐다. 가입·비밀번호 재설정 화면이 공통으로 쓴다.

- **이메일 칸**: 올바른 이메일이면 `인증 코드 발송` → 보내는 중 로딩 → 발송 뒤에는 `재발송`(60초 동안 `재발송 (N초)` 비활성) → 인증이 끝나면 초록 체크와 `변경`(접근성 이름은 "다른 이메일로 변경").
- **인증 코드 칸**(발송 뒤에만): 칸 안 오른쪽의 `인증 확인`(확인 중에는 로딩). 칸 아래에는 작은 글자 버튼 `이메일 변경`만 둔다.
- 인증 완료 문구는 화면에는 보이지 않고 스크린리더에만 읽힌다.
- 결과가 난 뒤 아이디를 고치면 결과가 초기화되어 다시 `중복 확인` 버튼이 나온다. 확인하지 않고 가입하면 "아이디 중복 확인을 해주세요." 안내가 나온다.

## 입력 검증 표시

- 회원가입 폼은 **입력칸을 한 번 벗어난 뒤부터** 형식이 맞지 않으면 테두리와 안내를 `danger` 색으로 바꾸고(`aria-invalid` 포함), 고치는 즉시 사라진다. 입력하는 도중에는 보여주지 않아 빨갛게 깜빡이지 않는다.
- 값이 비어 있으면 벗어나도 보여주지 않고 **제출할 때만** 안내한다. 제출·서버 오류가 있으면 그것을 먼저 보여준다.
- 모든 입력칸에는 예시 문구(`placeholder`)를 둔다. 힌트(`hint`)는 규칙 설명으로 따로 유지한다.
- 검사 규칙은 `features/auth/validation.ts`에 있고 백엔드 규칙과 맞춘다. 서버가 최종 판단한다.

## 접근성

- 포커스 링은 전역 `:focus-visible`로 `accent` 색을 쓴다.
- 입력의 에러·힌트는 `aria-describedby`로 연결하고, 에러는 `aria-invalid`를 함께 쓴다.
- 운동 경험 선택은 시각적으로 알약 버튼이지만 실제로는 라디오 그룹(`fieldset`)이다.
- 흰 바탕 위 `accent`, `ink-secondary` 텍스트는 일반 텍스트 대비 기준(4.5:1)을 넘기는 값만 쓴다.

## 미정

- 다크 모드, 아이콘
- 공식 디자인 시안이 나온 뒤 토큰 값과 컴포넌트 모양 교체

- 회원가입의 비밀번호·비밀번호 확인·닉네임도 아이디와 같은 모양이다: 올바르면 칸 안 초록 체크, 틀리면 빨간 느낌표 + 툴팁(`FieldStatus`), 칸 아래 문구는 스크린리더용으로만 둔다.

- 아이디·이메일·인증 코드의 **형식 오류**도 같은 느낌표 + 툴팁으로 보여준다. 이 오류가 있을 때는 `중복 확인`·`인증 코드 발송` 버튼이 없어 자리가 겹치지 않는다. 인증 코드 칸의 `인증 확인` 버튼은 6자리를 모두 입력했을 때만 나타난다. 서버가 알려주는 오류(코드 불일치, 이미 가입된 이메일 등)는 버튼과 자리가 겹쳐 아직 칸 아래 문구로 둔다.

## /home 히어로

- 살구색(`primary`) 둥근 카드에 왼쪽은 문구와 `brand` 버튼, 오른쪽은 사진(3:2)이다. 사진 원본이 452px라 카드 안 오른쪽 약 45% 폭(약 460px)에서만 쓴다. 풀폭으로 늘리면 흐려진다.
- 슬라이드의 이동 수단은 버튼이 아니라 **밑줄 링크 + 화살표**다(`brand-text` 색, 가리키면 코코아 색으로 바뀌고 화살표가 살짝 움직임). 문구와 사진이 주인공이 되도록 조용하게 둔다.
- 슬라이드 문구는 운동 이름 없이 상태·감정 중심이고, 운동이 정해지지 않아 모든 버튼이 운동 고르기(`/workouts`)로 간다. 두 번째 슬라이드는 닉네임과 임신 주차로 인사한다.
- 이미지는 `src/features/home/assets`에 있다 (`hero-stretch-warm`, `hero-stretch-window`, `hero-meditation`).

## /workouts 운동 고르기

- 살구색(`primary-soft`) 화면에 `/records`와 같은 머리글(살구색 알약 "오늘도 한 걸음", 제목 `text-4xl`, 한 줄 설명)을 쓴다. 좁은 화면에서는 카드가 한 줄로 쌓이고 `lg` 이상에서 2열이 된다.
- 1단계는 "운동 모드"·"자세 배우기" 카드를 함께 보여준다(`lg`에서 2열). 2단계는 고른 모드의 운동 카드(Side Kick, 준비 중인 운동)를 같은 2열로 보여준다. 카드는 `workout-catalog.ts`의 `WORKOUTS`에서 만든다. 2단계에서는 제목이 "{모드}, 어떤 운동을 할까요?"로 바뀌고 "다른 모드 보기" 밑줄 링크가 나온다. 좁은 화면에서는 카드 목록 아래 가운데에, `lg` 이상에서는 머리글 줄 오른쪽 끝에 놓인다(링크는 하나이고 CSS로 위치만 바뀐다).
- 카드는 흰 바탕에 `ring-primary-strong` 테두리의 `rounded-3xl`이다. 위에 16:9 사진(`features/workouts/assets`, `object-cover`, `loading="lazy"`; 모드 카드는 모드별 사진, 운동 카드는 운동별 사진이며 준비 중인 운동은 요가 매트·물병 정물 사진), 제목·한 줄 설명, 구분선 아래에 `sage-soft` 칩과 `brand` 알약 버튼 모양의 문구(카드 전체가 하나의 링크)가 놓인다. 운동 카드의 칩·버튼 문구는 고른 모드의 것을 쓴다. 가리키면 그림자가 생긴다.
- 아직 연결되지 않은 운동은 링크가 아닌 흐린 카드에 버튼 대신 "준비 중" 알약을 단다.
- 맨 아래에 `sage-soft` 안내 박스로 "운동을 시작하기 전에 개인의 건강 상태와 의료진의 운동 제한 권고를 확인해 주세요."를 두 단계 모두에서 보여준다.

## /workouts/:workoutId/:mode/ready 운동 준비

- 운동 카드를 누르면 가는 준비 페이지. `/workouts`와 같은 살구색 화면·머리글 구성이고 "← 운동 고르기"(들어온 `?mode=`로 복귀), 알약 "{운동} · {모드}", 제목 "운동 환경을 준비해 볼까요?"가 나온다.
- 좁은 화면은 단일 컬럼(체크리스트 카드만), `lg` 이상에서 왼쪽 준비 사진(`ready-workout.jpg`, `object-cover`, 좁은 화면에서는 숨기고 `loading="lazy"`라 받지 않음)과 오른쪽 카드로 나눈다(1.1fr : 1fr).
- 카드: 제목 "운동 전 준비사항", 오른쪽에 "체크 완료 N/M" 알약, 체크박스 줄(체크하면 `primary` 면), 카메라 안내 한 줄, `brand` "운동 화면으로 이동 →" 버튼. 모든 항목을 체크하기 전에는 버튼이 비활성이고 아래에 이유를 적는다. 체크리스트는 모드별로 `workout-catalog.ts`의 `checklist`에 둔다.
- 맨 아래 `sage-soft` 박스에 휴식 안내(`SAFETY_NOTICE`)와 건강 확인 안내(`HEALTH_NOTICE`)를 함께 보여준다.
- 카메라는 이 페이지에서 켜지 않는다. 운동 화면이 열릴 때 권한을 요청한다. 시안에 있던 "카메라 선택 사용"은 두 운동 화면이 카메라를 필수로 쓰므로 넣지 않았다.

## /workouts/sidekick/check/:mode 운동 환경 점검

- 준비 페이지 다음 단계. 준비 페이지와 같은 살구색 화면·머리글 구성("← 운동 고르기", 알약 "Side Kick · {모드}", 제목 "운동 환경을 확인할게요")이다.
- 좁은 화면은 카메라 → 점검 카드 순으로 쌓고, `lg` 이상에서 왼쪽 카메라(`rounded-3xl`, 가이드는 흰 점선 테두리)와 오른쪽 카드로 나눈다(1.1fr : 1fr).
- 카드: 제목 "촬영 환경 점검", 항목 3줄(운동 대상자·전신 인식·촬영 구도). 각 줄은 `StatusIcon`(확인 중 로딩, 정상 초록 체크, 문제 빨간 느낌표)과 결과 문구이고 정상이면 `sage-soft` 면이다. 아래에 상태 문구(`role="status"`)와 2초 유지 진행 막대(`brand-text`), `brand-outline` "취소" 버튼이 놓인다.
- 카메라 오류는 카드 안에 `alert`와 `brand` "카메라 다시 시도" 버튼으로 보여준다. 맨 아래에 준비 페이지와 같은 `sage-soft` 안내 박스를 둔다.
- 취소와 잘못된 모드는 `/workouts`로 간다(개발용 `/dev/sidekick/check`는 `/dev/sidekick/start`).

## /records 운동 기록 캘린더

- 머리글: "오늘도 한 걸음" 알약 라벨, 제목 "나의 운동 기록", 한 줄 설명. 아래에 흰 캘린더 카드와 살구색(`primary`) 요약 카드가 놓인다. 좁은 화면에서는 위아래로 쌓고 `lg` 이상에서 좌우(1.1fr : 1fr)로 나눈다.
- 캘린더 카드: 제목 "운동 캘린더", 오른쪽에 "2026년 10월"과 이전·다음 달 원형 버튼(다음 달은 이번 달에서 비활성). 요일 줄은 살구색 알약이고 토·일요일은 `danger`색이다(날짜 숫자도 같다). 날짜는 일요일부터 시작하며 1일 앞은 비운다.
- 날짜 칸: 운동을 마친 날은 `primary` 면과 `brand-text` 점, 선택한 날은 `brand` 면과 `on-brand` 굵은 글자(점은 `on-brand`), 오늘은 `brand-text` 1px 테두리. 날짜는 버튼이라 `aria-pressed`로 선택을, `aria-current="date"`로 오늘을 알리고, 라벨은 "10월 19일 월요일, 운동 기록 있음"처럼 읽힌다. 운동을 마친 날은 `is_completed`인 기록이 있는 날이고, 중단·진행 중 기록은 표시하지 않는다.
- 요약 카드: 선택한 날짜 알약("10월 19일 · 운동 기록")과 "기록 완료/기록 없음", 제목, 전체 날짜. 그 아래 큰 빈 영역(`records-report-slot`)은 AI 에이전트의 날짜별 요약 리포트가 들어올 자리다.
- 달을 넘기면 선택을 비우고(이번 달로 돌아오면 오늘을 다시 선택) 그 달 범위로 다시 조회한다. 조회에 실패하면 캘린더 위에 `alert`와 "다시 시도" 버튼을 보여준다.
- 날짜는 서버가 KST로 계산해 `date`로 내려준다. 오늘·이번 주 계산은 브라우저 로컬 시간이라 한국 밖에서 쓰면 하루 어긋날 수 있다.

## /home 이번 주 운동 카드

- 위에서 아래로: 제목 "이번 주 운동"과 오른쪽 "운동 기록 보기 →" 링크 → 한 줄 요약(`text-xl`) → 월~일 7칸(요일 글자 위, 36px 원 아래, 폭을 균등하게 채움) → 오늘 행동 → 응원 한마디. 왼쪽 여정 카드와 높이를 맞추므로 행동 영역을 `mt-auto`로 아래에 붙인다.
- 요약: 운동한 날이 있으면 "N일 운동했어요", 없으면 "첫 운동을 시작해 볼까요?"(제목이 이미 "이번 주"라 반복하지 않는다). 좁은 카드에서도 한 줄이 되도록 `text-xl`과 `whitespace-nowrap`을 쓰고, 카드의 다른 문구도 모두 한 줄이 되도록 짧게 둔다. 목표 횟수는 두지 않아 미달 느낌을 주지 않는다. 불러오는 동안은 비워 두되 높이는 지킨다.
- 요일 원: 운동을 마친 날은 `brand` 면과 체크 아이콘, 아닌 날은 `primary` 면과 날짜 숫자, 오늘은 `brand-text` 링과 굵은 글자. 끝내지 않은 기록은 운동한 날로 치지 않는다.
- 오늘 행동: 오늘 운동을 마쳤으면 세이지색 알약 "오늘 운동 완료"를 보여준다. 운동 시작 버튼은 두지 않는다(시작은 히어로가 안내한다). 불러오는 중에는 아무것도 보여주지 않고, 기록 조회에 실패하면 오류 알림 없이 기본 응원 문구만 보여주며 요약 문구·완료 체크·"오늘 운동 완료"처럼 기록에 기대는 내용은 숨긴다.
- 응원 문구는 상태에 따라 "오늘도 수고했어요"(오늘 마침) / "쉬어가는 날도 괜찮아요"(이번 주에 했지만 오늘은 아직) / "오늘도 천천히, 내 속도로"(이번 주 기록 없음)이다. 평가나 의학적 조언처럼 읽히지 않는 말투를 유지한다.

## 랜딩(`/`)과 푸터

- 랜딩은 살구색 계열로 구간을 번갈아 칠한다: 히어로(`primary-soft`, 넓은 면에 대표 색을 크게 칠하면 무거워 보여 연하게 둔다) → 기능 소개(`primary`, 흰 카드 + `primary-strong` 테두리) → 시작 방법(흰 바탕) → 마지막 안내(`primary-soft`, 아래 푸터와 이어진다). 제목·본문은 `cocoa`, 강조 글자와 숫자는 `brand-text`다.
- 랜딩 히어로 뒤에는 운동하는 사진이 아주 흐릿하게 비친다(`src/features/landing/assets/hero-bg-meditation.jpg`). 사진은 **96px로 줄인 약 3KB짜리**를 크게 늘려 써서 흐림 효과가 따로 필요 없다. 그 위에 `primary-soft` 25% 막을 덮고, 글자가 놓이는 가운데에는 92%까지 짙은 타원형 막을 따로 얹어 양옆의 사진(왼쪽 창, 오른쪽 화분)이 더 잘 보이게 하며, 아래쪽은 바탕색으로 녹아들게 한다. 장식이라 `alt=""`·`aria-hidden`이다. 글자 영역에서 가장 어두운 사진 부분까지 포함해도 소제목 4.8:1, 보조 문구 5.8:1, 제목 11.9:1(모두 4.5:1 이상)을 유지하는 것이 기준이다.
- 랜딩 버튼은 `brand`(채움)와 `brand-outline`(테두리) 변형을 쓴다. 푸터는 `primary` 바탕에 `cocoa-secondary` 글자다. 푸터는 화면을 많이 차지하지 않도록 위아래 여백 16px(`py-4`)에 두 문구 사이 간격 6px로 작게 두었다(넓은 화면 약 56px, 좁은 화면 약 94px).

## 화면 색 적용 현황

- 모든 화면(헤더, 푸터, 랜딩, 홈, 내 정보, 로그인, 회원가입, 비밀번호 재설정, 가입 마무리, 운동 고르기, 404, 로딩)이 살구색 계열이다. `PageShell tone="warm"`이 배경(`primary-soft`)과 제목·설명 글자(`cocoa`)를 정한다.
- 주 버튼은 `brand`, 보조 버튼은 `brand-outline`, 링크는 `TextLink tone="brand"`(`brand-text`)를 쓴다. 위험한 동작(탈퇴)은 의미 색인 빨강을 유지한다.
- 포커스 링은 모든 화면에서 `brand`다. 입력칸 테두리(`field`)와 오류 표시(분홍 배경·빨간 테두리)는 기존 그대로다.
- 파랑 `accent`와 `Button`의 `primary`/`secondary` 변형은 더 이상 화면에서 쓰지 않는다. 쓰는 곳이 생기기 전까지 정의만 남겨 둔다.

## 서비스 색

서비스 색(살구·코코아·세이지)은 디자인 시안에서 추출한 값으로 확정했고, 바꾸는 기능은 없다. 값은 `src/index.css`의 `@theme`에 있다.

- **글자·그래픽 대비**: 브랜드 색(`brand`)이 밝아 버튼 글자(`on-brand`)는 어두운 코코아를 쓴다. 강조 글자·포커스 링·진행 막대 같은 의미 있는 그래픽은 `brand`가 아니라 `brand-text`·`focus`를 써서 대비를 지킨다.
